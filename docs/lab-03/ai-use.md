## My Reflection

การดำเนินงานใน **Lab 3: Authentication, Role-Based Access Control, and Ticket Lifecycle Operations** ถือเป็นก้าวกระโดดที่สำคัญอย่างยิ่งในการยกระดับระบบ TokTickIT จากเว็บแอปพลิเคชันที่รองรับเฉพาะ Requester แบบพื้นฐานใน Lab 2 สู่ระบบ Enterprise IT Service Management เต็มรูปแบบที่มีความมั่นคงปลอดภัยสูง รองรับผู้ใช้งาน 3 บทบาท (Requester, IT Staff, Administrator) พร้อมสถาปัตยกรรมการจัดการสิทธิ์ (RBAC), วงจรชีวิตตั๋ว (Ticket Lifecycle State Machine), การสื่อสารสองชั้น (Public Comments vs. Confidential Internal Notes), และระบบบริหารจัดการผู้ใช้ที่รัดกุม

### 1. ประสบการณ์และการทำงานร่วมกับ AI Assistant (Human-AI Collaboration)
ตลอดทั้ง Sprint 3 การใช้งาน AI ในบทบาทของ Pair Programmer ขั้นสูงช่วยเพิ่มความเร็วและประสิทธิภาพในการพัฒนาได้อย่างมีนัยสำคัญ:
- **Architecture & Foundation**: AI ช่วยวิเคราะห์ข้อกำหนดใน Handout และร่างเอกสารทางวิศวกรรม (`specification.md`, `ui-spec.md`, `api-spec.md`, `tests.md`) ที่มี Acceptance Criteria Traceability อย่างชัดเจน ช่วยสร้างกรอบการทำงานที่รัดกุมก่อนเริ่มลงมือเขียนโค้ดจริง
- **Domain Modeling & Pure Functions**: AI ช่วยแปลงกฎทางธุรกิจที่ซับซ้อนให้กลายเป็น Pure Functions ที่ทดสอบได้ง่าย เช่น Password Validator (BR-07), Status Transition State Machine Matrix (BR-14), In-Memory Token Revocation Store (BR-09), และ Admin Safety Validators (BR-21, BR-22)
- **Comprehensive Test-Driven Approach**: AI ช่วยสร้างชุดทดสอบระดับ Unit, API Integration, Component UI, และ Playwright E2E ที่ครอบคลุมทุกกรณีทั้ง Positive, Negative, Boundary, Edge Cases, และ Concurrent Requests ทำให้ทีมมั่นใจได้ว่าระบบไม่มี Regression เกิดขึ้นตลอดการพัฒนา

### 2. บทบาทสำคัญของ Human-in-the-Loop และการคิดเชิงวิพากษ์ (Critical Thinking)
แม้ AI จะมีความสามารถสูง แต่การพึ่งพา AI โดยปราศจากการตรวจสอบอย่างเข้มงวดอาจนำมาซึ่งปัญหาเชิงเทคนิคและช่องโหว่ความปลอดภัยที่แฝงอยู่ ในแล็บนี้ มีหลายสถานการณ์สำคัญที่การตรวจสอบและการคิดเชิงวิพากษ์ของมนุษย์ (ร่วมกับ Peer Review) เข้ามามีบทบาทชี้ขาด:
1. **JWT Secret Security (Handout §6.1)**: AI เผลอใส่ hardcoded fallback string ในโค้ดดั้งเดิม ซึ่งหากปล่อยหลุดขึ้น Production จะสร้างความเสี่ยงใหญ่หลวง จึงต้องสั่งให้ปรับเป็น strict refusal ใน production และใช้ ephemeral cryptographically random secret ใน dev/test
2. **Authentication Bypass & Legacy Fallback Vulnerability**: ในระหว่างการพัฒนาฟีเจอร์ Requester พบว่า middleware fallback ยังคงยอมรับ `x-requester-id` โดยตรงหากไม่ส่ง Bearer token ซึ่งเปิดช่องให้ผู้ไม่ประสงค์ดีปลอมแปลงเป็น Requester คนอื่นได้ ผู้พัฒนาจึงได้สั่งปิด legacy bypass ในโหมด production ทันที
3. **Database Race Condition & P2002 Handling**: ในขั้นตอนสร้างผู้ใช้ใหม่ การใช้ `findUnique` ควบคู่กับ `create` แบบเดิมอาจเกิด race condition เมื่อมี concurrent requests ส่งเข้ามาพร้อมกัน ผู้พัฒนาจึงได้เพิ่มการดักจับ Prisma error code `P2002` เพื่อแปลงเป็น `409 DUPLICATE_EMAIL` ที่ถูกต้องตาม API Spec
4. **Token Collisions ในการทดสอบ**: ในระหว่างรัน E2E Tests พบว่าการล็อกเอาต์แล้วล็อกอินใหม่ภายในวินาทีเดียวกันทำให้ JWT string มีค่าซ้ำเดิมเนื่องจาก `iat` มีความละเอียดระดับวินาที ส่งผลให้โทเค็นใหม่ถูกมองว่าเป็นโทเค็นที่ถูก Revoke ไปแล้ว การใส่ `jwtid` (`crypto.randomUUID()`) ใน payload จึงเข้ามาแก้ปัญหานี้ได้อย่างเด็ดขาด

### 3. ทักษะทางวิศวกรรมซอฟต์แวร์ที่ได้รับการพัฒนา
จากการลงมือปฏิบัติจริงในแล็บนี้ ทักษะที่ได้รับการฝึกฝนและพัฒนาอย่างเด่นชัด ได้แก่:
- **Defense in Depth**: การวางระบบความปลอดภัยแบบหลายชั้น ทั้งระดับ Database (Constraints), Domain Layer (Validators), API Layer (Middlewares, Token Revocation, Role Guards), และ UI Layer (Route Guards, Context Gating)
- **End-to-End Testing & Visual Verification**: การเขียน Automated E2E Tests ด้วย Playwright ที่จำลองการเดินทางของผู้ใช้จริง (User Journey) ครอบคลุมตั้งแต่การล็อกอิน, การบังคับเปลี่ยนรหัสผ่านเริ่มต้น, การเคลมตั๋ว, การปรับเปลี่ยนสถานะพร้อมบันทึกสรุปผล, และการทดสอบ Responsive ข้ามขนาดหน้าจอ Desktop, Tablet, และ Mobile อย่างเป็นรูปธรรม
- **Teamwork & Git Workflow**: การทำงานร่วมกันผ่าน Git Feature Branching (`feature/3-1` ถึง `3-9`), Pull Request Reviews และการบันทึก Peer Review Feedback อย่างมีแบบแผน ทำให้การผสานงานในโปรเจกต์มีความโปร่งใสและเป็นมืออาชีพ

โดยสรุป AI Assistant เป็นเครื่องมือทรงพลังที่ช่วยเร่งผลิตภาพและช่วยให้การออกแบบระบบมีความสมบูรณ์แบบยิ่งขึ้น แต่คุณภาพสูงสุด ความปลอดภัย และความถูกต้องตามวัตถุประสงค์ของระบบ ยังคงต้องอาศัยการกำกับดูแล การตัดสินใจ และความรับผิดชอบเชิงวิศวกรรมของผู้พัฒนาเป็นหัวใจสำคัญสูงสุดเสมอ

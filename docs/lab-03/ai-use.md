## My Reflection

การดำเนินงานใน **Lab 3: Authentication, Role-Based Access Control, and Ticket Lifecycle Operations** ถือเป็นก้าวกระโดดสำคัญในการยกระดับระบบ TokTickIT จากเว็บแอปพลิเคชันพื้นฐานใน Lab 2 สู่ระบบ Enterprise IT Service Management เต็มรูปแบบ รองรับผู้ใช้งาน 3 บทบาท (_Requester, IT Staff, Administrator_) พร้อมสถาปัตยกรรมการจัดการสิทธิ์ (RBAC), วงจรชีวิตตั๋ว (Ticket Lifecycle State Machine), การสื่อสารสองชั้น (Public Comments vs. Confidential Internal Notes) และระบบบริหารจัดการผู้ใช้ที่รัดกุม

### 1. ประสบการณ์และการทำงานร่วมกับ AI Assistant (Human-AI Collaboration)

ตลอดทั้ง Sprint 3 การใช้งาน AI ในบทบาท Pair Programmer ช่วยเพิ่มความเร็วและคุณภาพในการพัฒนาอย่างมีนัยสำคัญ:

- **Architecture & Foundation:** AI ช่วยวิเคราะห์ข้อกำหนดใน Handout และร่างเอกสารทางวิศวกรรม (`specification.md`, `ui-spec.md`, `api-spec.md`, `tests.md`) ที่มี Acceptance Criteria Traceability ชัดเจน ทำให้เห็นภาพรวมและขอบเขตงานก่อนเริ่มเขียนโค้ด
- **Domain Modeling & Pure Functions:** AI ช่วยแปลงกฎทางธุรกิจที่ซับซ้อนให้อยู่ในรูป Pure Functions ที่แยกทดสอบได้ง่าย เช่น Password Validator (BR-07), Status Transition State Machine Matrix (BR-14), In-Memory Token Revocation Store (BR-09) และ Admin Safety Validators (BR-21, BR-22)
- **Comprehensive Test-Driven Approach:** AI ช่วยวางโครงชุดทดสอบทั้ง Unit, API Integration, Component UI ไปจนถึง Playwright E2E ที่ครอบคลุมทั้ง Positive, Negative, Boundary, Edge Cases และ Concurrent Requests ป้องกันปัญหา Regression ตลอดการพัฒนา

### 2. บทบาทของ Human-in-the-Loop และการคิดเชิงวิพากษ์ (Critical Thinking)

แม้ AI จะสร้างโค้ดได้อย่างรวดเร็ว แต่การตรวจสอบเชิงลึกและการตัดสินใจของมนุษย์ยังคงเป็นจุดชี้ขาดด้านความมั่นคงปลอดภัยและเสถียรภาพของระบบ:

1. **JWT Secret Security (Handout §6.1):** AI เผลอใส่ Hardcoded Fallback String ไว้ในโค้ดตั้งต้น หากหลุดขึ้น Production จะกลายเป็นช่องโหว่ร้ายแรง จึงสั่งปรับโค้ดให้ปฏิเสธการทำงานทันทีหากไม่มี Environment Variable บน Production และให้ใช้ Ephemeral Cryptographically Random Secret สำหรับ Dev/Test
2. **Authentication Bypass & Legacy Fallback:** ระหว่างพัฒนาฟีเจอร์ Requester พบว่า Middleware ยังยอมรับ Header `x-requester-id` โดยตรงหากไม่แนบ Bearer Token ซึ่งเปิดช่องให้เกิดการปลอมแปลงตัวตน จึงสั่งปิด Legacy Bypass ทั้งหมด
3. **Database Race Condition & Prisma P2002:** การตรวจสอบความซ้ำซ้อนของอีเมลด้วย `findUnique` ก่อน `create` เสี่ยงต่อการเกิด Race Condition เมื่อมี Concurrent Requests ผู้พัฒนาจึงเพิ่มการดักจับ Prisma Error Code `P2002` ในชั้น Database เพื่อแปลงเป็น `409 DUPLICATE_EMAIL` อย่างแม่นยำ
4. **Token Collisions ในการทดสอบ:** ระหว่างรัน Playwright E2E พบว่าการล็อกเอาต์แล้วล็อกอินใหม่ภายในวินาทีเดียวกันทำให้ JWT ซ้ำเดิมเนื่องจาก Timestamp `iat` บันทึกระดับวินาที ส่งผลให้โทเค็นใหม่ถูกมองว่าอยู่ใน Blacklist จึงแก้ไขโดยฝัง `jwtid` ด้วย `crypto.randomUUID()` เข้าไปใน Payload

### 3. ทักษะทางวิศวกรรมซอฟต์แวร์ที่ได้รับการพัฒนา

- **Defense in Depth:** การวางโครงสร้างความปลอดภัยหลายชั้น ตั้งแต่ระดับฐานข้อมูล (Unique Constraints), ชั้นโดเมน (Business Validators), ชั้น API (Middlewares, Token Revocation, RBAC Guards) ตลอดจนชั้น UI (Protected Routes, Context Gating)
- **End-to-End Testing & Visual Verification:** การเขียน Automated E2E Tests ด้วย Playwright จำลองพฤติกรรมผู้ใช้จริง ครอบคลุมตั้งแต่การล็อกอินครั้งแรก การบังคับเปลี่ยนรหัสผ่าน การจัดการตั๋ว ไปจนถึงการทดสอบความเข้ากันได้ของ Responsive Layouts บน Desktop, Tablet และ Mobile
- **Teamwork & Git Workflow:** การจัดการซอร์สโค้ดผ่าน Git Feature Branching (`feature/3-1` ถึง `3-9`), การจัดทำ Pull Request Reviews และการบันทึกข้อเสนอแนะใน Peer Review อย่างมีแบบแผน ช่วยรักษาคุณภาพของโค้ดให้สม่ำเสมอ

AI Assistant ทำหน้าที่เป็นตัวเร่งผลิตภาพและช่วยให้การออกแบบระบบมีความครบถ้วนรัดกุม อย่างไรก็ตาม ความปลอดภัย เสถียรภาพ และความถูกต้องของระบบตามเป้าหมายทางวิศวกรรม ยังคงต้องพึ่งพาการกำกับดูแลและการตัดสินใจอย่างมีวิจารณญาณของผู้พัฒนาเป็นสำคัญที่สุด
